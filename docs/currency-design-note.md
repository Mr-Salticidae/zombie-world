# 货币系统：为什么是这个形状

反馈里提到「游戏没有货币系统」。做成了**局内货币 + 波间商店，只卖消耗品**。
这份文档记的是**为什么排除了别的做法**——数值和实现细节看代码与 README，
这里只留那些看代码看不出来的判断。

## 落地成什么样

| | |
|---|---|
| 怎么赚 | 击杀掉金币，100px 内自动飞过来；金币越旧吸附半径越大（最大 300px） |
| 面值 | `击杀基础分 ÷ 5`：普通僵尸 2、红恶魔 8、BOSS 24~88。**不乘连击倍数** |
| 怎么花 | 一波打完自动弹「波间补给」，买完点「开打」进下一波 |
| 卖什么 | 每把已解锁枪的弹药包、医疗包（+35 血 / 40）、无双充能（+1 次 / 120，上限 2） |
| 弹药包 | 量 = `give ÷ 2`（跟地上捡的补给一致），价 = `20 + 解锁门槛 × 2` |
| 存不存 | 不存。死了归零，不进 localStorage，不进云存档 |

## 三个「不」，以及为什么

### 不卖枪

枪的所有权归**连击倍数**（×3 到 ×20 依次解锁），这是这一作的核心手感：
「打得越猛枪越强，挨一下倒退一半」。钱只要能买枪，这条线当场作废——
玩家会发现苟着攒钱比追连击稳，于是整个战斗节奏反转成保守打法。

所以货架上一件枪都没有，`buyItem` 也只认 `ammo` / `heal` / `ult` 三类，
单测里有一条专门钉死这件事（「只卖消耗品：货架上不存在任何一件能买到枪的东西」）。

### 不跨局

跨局货币（永久解锁、起始武器、被动加成）会**当场把排行榜打废**。
现在的榜只收标准难度，比的正是同一套初始条件；一旦有人带着永久加成上榜，
榜就变成「谁刷得久」。要救只有两条路，都不划算：

- 把带加成的局排除出榜 → 那加成就没人要了
- 给榜分档 → 工作量翻倍，而榜本身的人气还没验证过

外加一个现实问题：**存哪。** Toy JS SDK 目前用到的只有 `getRankList` / `submitScore`
（见 `script.js` 的 `rankReady()`），存档只能落 localStorage；
而玩家几乎全在手机 App 内嵌 WebView 里，那个环境的本地存储什么时候被清掉不由我们决定。
「攒了十局的进度一夜清零」比没有进度更糟。

### 钱不乘连击倍数

得分是 `基础分 × 倍数`，钱是 `基础分 ÷ 5`。故意不让倍数管钱：
倍数已经在管武器解锁了，再让它管钱，后期会同时出现「枪全解锁」和「钱多到没处花」，
两条成长线一起失重。现在的曲线是**收入随波次涨、价钱不变**，
所以早期一波只够买一件，后期能买四五件——而后期的弹药消耗本来也是四五倍。

## 波间商店而不是随时可开

- 波间那 3 秒本来就是**纯空白**，放一个决策点是净收益
- 手机右下角已经挤了「换枪 + 无双」两个悬浮键，再加一个要重排整个触屏布局
- 「打着打着开商店」会退化成刷钱-买-刷钱的循环，把战斗节奏切碎

单人时商店会**一直等你**（`waveRest` 冻住，点「开打」才继续）；
联机不能卡住对方，所以波间延长到 9 秒、双方各买各的、时间到自动开打。
商店是浮在 `play` 之上的一层，**不参与 `state`**——这样它在联机时不会把战局暂停掉，
单人时也不用为了开个商店去动状态机。

## 联机怎么结账

客机没有权威。购买请求跟无双一样走输入通道（`buySeq` + `buy`），房主收到后调 `buyItem` 结账：

- 只认**序号递增**的那一次，网络重传不会重复扣钱
- `buyItem` 自己校验解锁 / 余额 / 是否已满，所以对面发来的 id 不需要被信任
- 客机本地先乐观扣一次给即时反馈，下一份快照会纠正

## 下一步能调什么

按「先动哪个最省事」排：

1. **价钱**：`ammoPackCost` 一条公式管九把，`20 + unlock*2` 里两个数
2. **收入**：`coinValue` 的除数（现在是 5）
3. **吸附**：`COIN_MAGNET`（100）和「越旧吸得越远」那条曲线
4. **货架**：想加临时增益（下一波双倍伤害 / 护盾）就往 `shopCatalog` 里加一类，
   `buyItem` 补一个分支，UI 不用动

真要调之前先看一眼实测曲线（README 的《波间商店》一节里有一张十波的收支表）。
