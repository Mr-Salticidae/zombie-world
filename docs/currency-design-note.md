# 货币系统：设计前的约束与选型（还没实现）

反馈里提到「游戏没有货币系统」。这一版没有做，先把**约束**和**两条可选路线**记下来，
免得下次动手时又从零开始争论。

## 现在游戏里已有的「经济」

看清楚这几条很重要——货币不是往空地上盖房子，是往一套已经在跑的经济里插东西：

| 已有的东西 | 怎么拿 | 作用 |
|---|---|---|
| 得分 `score` | 击杀 × 连击倍数 | 只进排行榜，局内没有任何用途 |
| 连击倍数 `multiplier` | 连续击杀，受伤减半 | **武器解锁的唯一钥匙**（×3 到 ×20 共 8 把） |
| 弹药 | 击杀掉落 + 解锁时附赠 | 限制强枪的使用时长 |
| 无双充能 | 每 50 杀 | 一次性爆发 |

关键：**武器解锁挂在连击上，不是挂在资源上。** 这是这一作的核心手感——
「打得越猛，枪越强；挨一下，倒退一半」。任何货币方案第一件事就是回答
**它跟连击解锁是什么关系**，答不上来就会变成两套互相打架的成长线。

## 两条路线

### A. 局内货币（run-scoped）

击杀掉钱，钱只在这一局有效，死了清零。花在哪：局内商店（波间弹药 / 治疗 / 临时增益 /
提前买断某把枪）。

- 好：不碰存档、不碰排行榜公平性，一局自洽，改起来风险最低
- 好：给「波间那 2.2 秒」一个决策点，现在那段时间是纯空白
- 难：要新开一个商店界面，而手机竖屏的界面预算已经很紧（底部武器栏 + 三个悬浮键）
- 难：跟连击解锁重叠——如果钱也能买枪，连击那条线就废了。
  **要买就只买消耗品（弹药 / 血 / 一次性增益），枪的所有权仍然只由连击决定**

### B. 存档货币（meta-progression）

跨局累积，花在永久解锁：新角色、起始武器、被动加成。

- 好：给「重复开局」一个理由，留存曲线好看
- 致命难点一：**排行榜会当场失衡。** 现在的榜只收标准难度、比的是同一套初始条件；
  一旦有人带着永久加成上榜，榜就变成「谁刷得久」。要么把带加成的局排除出榜
  （那加成就没人要了），要么给榜分档（工作量翻倍）
- 致命难点二：**存哪。** Toy JS SDK 目前用到的只有 `getRankList` / `submitScore`
  （见 `script.js` 的 `rankReady()`），存档要么另找云存储接口、要么落 localStorage。
  落 localStorage 就是「换个浏览器进度没了」，而玩家几乎全在手机 App 内嵌 WebView 里，
  那个环境的本地存储什么时候被清掉不由我们决定
- 难点三：数值一旦上线就改不动了，改了就是「削弱已购内容」

## 倾向

**先做 A，而且只卖消耗品。** 理由是它不动排行榜、不需要存档、不跟连击解锁抢位置，
一局之内就能验证「有没有让波间变得更好玩」这一件事。
A 跑通了再谈 B 也不迟；A 都没人用，B 更不会有人用。

## 动手前要先定的三件事

1. **掉钱还是转换分数？** 掉钱要新粒子和新拾取逻辑；「得分的一部分自动折成钱」
   零新美术、零新交互，但少了「弯腰去捡」的手感
2. **商店开在哪一刻？** 波间自动弹（打断节奏，但保证被看见）还是按键随时开
   （手机上又要多一个悬浮键，而右下角已经挤了换枪 + 无双）
3. **卖什么，各卖多少钱？** 至少要先想清楚「钱最多能买到多少发加特林子弹」——
   这个数一旦定错，要么钱没用，要么弹药限制形同虚设
